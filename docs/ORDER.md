# จัดเรียงหน้า PDF · 1.13.0

เปิด **จัดเรียงหน้า PDF** แล้วกด **เพิ่ม PDF…** หรือวางหลายไฟล์จาก Explorer
ไฟล์แรกเป็นเอกสารหลัก; ไฟล์ต่อไปเพิ่มทุกหน้าก่อนตำแหน่งแรกที่เลือก หรือท้ายเอกสารเมื่อไม่เลือกหน้า
ภาพตัวอย่างโหลดเฉพาะบริเวณที่มองเห็น
แต่ละการ์ดแสดง **ใหม่** (ตำแหน่งในผลลัพธ์) และ **เดิม** (เลขหน้าในต้นฉบับ)
ตารางทางขวาตรวจลำดับใหม่/เดิมและชื่อไฟล์ได้ครั้งละ 25 รายการ เมื่อมีหลายต้นทางแสดงชื่อต้นทาง

- คลิกหน้าเพื่อเลือก; Ctrl+คลิกเพิ่ม/ลด และ Shift+คลิกเลือกช่วงตามลำดับใหม่
- ลากหน้าที่เลือกไปก่อนหรือหลังการ์ดปลายทาง เส้นสีน้ำเงินแสดงตำแหน่งแทรก
  ถ้าเลือกหลายหน้า หน้าที่เลือกจะย้ายพร้อมกันโดยรักษาลำดับระหว่างกัน
  เลื่อนที่ขอบบน/ล่างได้ และกด Esc เพื่อยกเลิกการลากก่อนปล่อย
- ลูกศร/Home/End/Page Up/Page Down เลื่อนจุดโฟกัส; Space เลือก/ลดหน้า
  Shift+ลูกศรเลือกช่วง, Ctrl+A เลือกทั้งหมด, Alt+ลูกศรย้ายหน้าที่เลือก
  หรือใช้ปุ่ม **ย้ายก่อน / ย้ายหลัง**; ช่องช่วงหน้าระบุตำแหน่งใหม่ เช่น `1-3,5`
- **ลบที่เลือก** หรือ Delete บนตารางการ์ด ลบหน้าที่เลือก ต้องเหลืออย่างน้อยหนึ่งหน้า
- **Undo / Redo** หรือ Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z บนตารางการ์ด ย้อน/ทำซ้ำการเพิ่ม ลบ ย้าย และคืนต้นฉบับ รวมการเลือกก่อนคำสั่ง; ช่องข้อความใช้ Undo ของช่องตามปกติ
- **คืนต้นฉบับ** คืนทุกหน้าในเอกสารหลักและนำหน้าที่เพิ่มออก โดยยังไม่เขียนไฟล์; Undo กลับได้
- **เริ่ม PDF ใหม่…** อ่านเอกสารหลักใหม่แล้วล้างประวัติเมื่อสำเร็จ; ยกเลิกหน้าต่างเลือกไฟล์/worker จะเก็บโต๊ะงานเดิม
- เลือกชื่อและโฟลเดอร์ ตรวจตาราง แล้วกด **บันทึก PDF ตามลำดับใหม่** หรือ Ctrl+Enter

ประวัติจำกัด 32 คำสั่งและผลรวม 100,000 page identities ต่อ Undo/Redo stack เมื่อเต็มทิ้งเก่าสุด; คำสั่งใหม่ล้าง Redo
โต๊ะงานจำกัด 64 ไฟล์/100,000 หน้าต้นทาง รวมไฟล์ที่ยังอยู่ในประวัติ ไม่มีภาพหรือสำเนา PDF ในประวัติ
ไฟล์ที่เพิ่มแล้วจะยังเก็บไว้อ้างอิงแม้คืนต้นฉบับ; ไม่เพิ่มไฟล์เดิมซ้ำ ให้ใช้ Undo หรือเริ่ม PDF ใหม่
บันทึกเสร็จยังเก็บโต๊ะงาน/ประวัติไว้ เปลี่ยนชื่อเพื่อส่งออกซ้ำ ปุ่มและช่องที่เลื่อนพ้นจอเผยเมื่อ Tab ถึง

การบันทึกตรวจหน้าที่เหลือไม่ซ้ำ เปิดเอกสารหลักในหน่วยความจำ เพิ่ม native pages แต่ละไฟล์ที่ใช้ครั้งเดียว แล้วลบ/ย้ายวัตถุหน้าเดิม
ไม่ rasterize ไม่เปลี่ยน DPI และไม่ลดคุณภาพ เนื้อหา/ภาพ/rotation/widgets/annotations
และ direct internal-link destinations คง page xref เดิม; bookmarks remap ไปยังลำดับใหม่
ไฟล์ชั่วคราวถูกเปิดตรวจจำนวนและลำดับ xref ก่อนเผยแพร่แบบไม่ทับไฟล์ที่มีอยู่
ตรวจ signature ต้นฉบับอีกครั้งก่อนเผยแพร่; ไม่เขียนกลับต้นฉบับ

**ยกเลิก** ใช้ loader และ token ร่วม รอ native operation ปัจจุบันจบแล้วล้าง staging
คืนเฉพาะไฟล์ของงานที่ยังไม่มีใครแก้ต่อ และคืน controls หลัง cleanup เพื่อเริ่มใหม่ได้
หากชื่อปลายทางมีอยู่แล้ว ให้เปลี่ยนชื่อก่อนเริ่มใหม่

ลิงก์/บุ๊กมาร์กไปหน้าที่ลบจะถูกนำออก ระดับ bookmarks ที่เหลือปรับให้ถูกต้อง
ฟอร์มชื่อซ้ำจากคนละไฟล์แยกชื่อเพื่อรักษาค่าอย่างอิสระ ขนาดหน้า CropBox และ rotation คงเดิม
PDF หลักเก็บ metadata/attachments เดิม; ไฟล์เพิ่มนำเข้าเฉพาะหน้าพร้อม links/annotations/forms/bookmarks
ไม่รวม attachments หรือ metadata ระดับเอกสารจากไฟล์เพิ่ม การลบหน้า **ไม่ใช่ redaction**
วัตถุที่ไม่แสดงอาจยังอยู่ใน PDF จึงไม่ใช้ลบข้อมูลลับถาวร

หลักฐาน: [native interaction / Poppler](order-verification-1.13.0.json), [export resources](organize-resources-1.13.0.json),
unit `tests/unit/test_pdf_order.py` ตรวจ link, bookmark, annotation, form value/การแก้ไข,
rotation, page text/pixels, cancellation/retry, collisions และการรักษาต้นฉบับ
ตรวจ 920×700 ที่ 100%/125% และ preview 240 หน้า; ใช้ process ร่วมหนึ่งตัว,
viewport ≤24, requests ≤16, cache 32/6 MiB โดยประมาณ

PDF ที่ต้องใช้รหัสผ่านและการรักษาความถูกต้องของลายเซ็นดิจิทัลยังไม่รองรับ
เอกสารที่มี JavaScript อ้างเลขหน้าตายตัวหรือ action พิเศษต้องตรวจพฤติกรรมใน PDF viewer
หลังเรียงใหม่; การย้ายหน้าไม่ rewrite script เหล่านั้น
ยังไม่รับรอง PC 2 คอร์/4 GiB/HDD จริง หรือ Windows 11 จากผลเครื่องพัฒนา
